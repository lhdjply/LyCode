| 项 | 状态 | 说明 |
| --- | --- | --- |
| MCP — HTTP/SSE 传输 | **未实现** | 只有 stdio 传输；远程 HTTP 服务器接不了 |
| MCP — `resources` / `prompts` | **未实现** | 只接了 `tools` 能力 |
| Skills — 斜杠命令 | **未实现** | 只能由模型按描述自己决定加载；输入框里没有 `/skill` 补全入口（`/compact`、`/help` 是内建命令，与 skills 无关） |
| 集成终端 | **未实现** | |
| 远程工作区 | **未实现** | `Workspace` 已保留 `identity` 与 `remoteSessionId` 字段 |
| 动态工作流 | **未实现** | |
| 归档历史的界面入口 | **未实现** | 压缩掉的消息已完整存进 `archived_message` 表，但界面上还没有"查看原始历史"的入口，只能从数据库读 |
| 切换语言后不重启即整体重译 | **未实现** | 已建好的控件不会自己重译（Qt 只在 `LanguageChange` 事件里重取文案，本窗口的控件文案是构造期写死的）。所以设置页保存后**弹窗询问是否立即重启**，一键生效；选"稍后"则状态栏保留提示。做成"逐控件重译"需要把上百处文案赋值搬进 `retranslateUi()`，风险高于收益 |
| 第三种语言 | **未实现** | 目前只有 `zh-CN` 这一份译文；加语言只需新增 `translations/lycode_<lang>.ts` 并在 `Translator` 里登记 |

已经可用、但**能力边界**需要知道的几项：

| 项 | 边界 |
| --- | --- |
| MCP（stdio + tools） | 握手是异步的；第一次发送会等它就绪（上限 8 秒），超时后就按"没有 MCP 工具"发出去 |
| Skills | 只有模型主动加载这一条路径；没有斜杠命令补全 |
| 上下文压缩 | 估算基于字符数（约 3 字符/token），不接模型的 tokenizer，因此是估值；工具输出按 30000 字符先截断再进上下文，微压缩只对超过 8000 字符的**旧**输出生效（小输出留着更有用） |
| 后台任务 | 分离式任务可跨重启；管道式（超时自动后台化）只在本进程存活期间运行 |
| 图片附件 | 只支持图片；非图片附件会明确告警后跳过 |
| Windows shell | 走 PowerShell（`pwsh` 优先）→ `cmd` 兜底，**不是 bash**。模型按实际 shell 的语法生成命令；可用 `LYCODE_SHELL` 覆盖 |
| Windows pid 复用校验 | **不可用**：没有启动时间指纹（只有 Linux 读 `/proc/<pid>/stat`），认领时无法识破 pid 被复用 |
| 界面翻译 | 源文案是**英文**，中文来自内嵌的 `zh_CN.qm`。因此中文界面**依赖翻译文件**：漏译的地方会显示英文。已有测试钉住"中文界面下按钮/菜单/工具文案必须是中文" |
| 翻译的覆盖范围 | **面向用户的都翻译**：`ui/` 全部 + `AgentRuntime` 的用户提示 + 各工具的**结果文案**（它们显示在工具卡片里）。**不翻译**的只有发给模型的那一类：系统提示词、工具与参数的 JSON Schema 说明（`scripts/check-translations.py` 会自动从源码提取这些说明并拒绝它们进 `.ts`） |

这一节刻意写得具体：把"没做"和"做了一半"分开，避免读代码的人以为某项已经可用。
